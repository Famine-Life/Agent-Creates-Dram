# 多用户会员制：产品、架构、UI 与实施计划

## Context

README.md 的“单用户 vs 多用户会员制”目前仍是规划表，实际系统还是内存单管理员、业务数据共享、全局 MCP Token、平台级任务并发。当前目标是在新分支完整落地该表，同时新增一版会员制的产品设计、架构设计和 UI 设计；三份新设计均新建独立文件，原有单用户版文档保持不动，而不是只增加账户页面。

已确认：
- 分支：`feature/multi-user-membership`，从当前干净的 `main` 创建；只创建分支和改代码，不擅自提交、推送或部署。
- 范围：README 全表完整闭环；本地默认 `mail=log`、`payment=mock`、`mq=db`，同时提供 SMTP、IJPay 2.9.7、RabbitMQ 生产适配。
- 会员：免费版、专业版、工作室版三档；积分充值与会员购买分开，权益、商品价格和模型计费均可配置。
- 注册：注册后可登录和管理自己的画布，验证邮箱后才允许 AI 生成和充值。
- 迁移：现有画布、素材、任务全部归当前 `AIGC_ADMIN_USERNAME` 管理员，保留 `workspace.id=1`。
- 无真实邮件、商户、RabbitMQ 凭据时，只验收本地与自动化测试，不宣称外部生产服务已联通。

## 一、产品设计与 UI 重设计

### 1. 产品规则

新增 `docs/product-design-membership.md`（保留 `docs/product-design.md` 原版不动），将产品从单用户画布升级为“个人创作空间 + 积分钱包 + 会员权益 + 管理后台”，明确：

- 用户角色：`USER` 与 `ADMIN`；管理员由已有用户提升，业务画布仍按个人隔离，管理后台只处理用户、订单、配额、审计和死信，不默认开放用户私人画布内容。
- 账户生命周期：注册、登录、邮箱验证、重新发送验证邮件、找回/重置密码、禁用账号、退出登录。
- 会员权益：每日积分额度、个人并发、最高分辨率、调度权重；`FREE / PRO / STUDIO` 首次启动由配置播种，之后后台修改不被重启覆盖。
- 积分规则：充值和会员订单分别创建；视频、图片、文本生成按模型与参数估价，提示词/画布保存等无 AI 调用操作不计费。
- 计费规则：每次生成尝试先冻结积分，成功实扣，明确失败/取消释放；提交结果未知时继续冻结并进入人工核对，防止重复扣费。积分不足写入零变动失败流水并标记 `INSUFFICIENT_BALANCE`，额度耗尽标记 `QUOTA_EXCEEDED`。
- 订单规则：积分商品和会员商品分别购买；金额使用分，订单保存价格与权益快照；支付回调验签、核对金额与商户信息，重复通知不重复入账。
- 画布规则：登录后先进入“我的画布”，可新建、重命名、复制、删除和进入画布；系统仍保证每个用户至少保留一个画布。
- 本地开发：log 邮件仅 local 暴露开发验证/重置链接；Mock 支付仅 local 可模拟成功，生产配置缺失时明确报错而不是静默 Mock。

### 2. 页面与导航

引入 Vue Router 4，避免继续用单个 `AuthGate.vue` 条件堆叠注册、重置、账户和后台页面。保留现有 Vue 3、Vite、Vue Flow 和主题变量。

- `/login`、`/register`、`/forgot-password`、`/reset-password`：统一品牌认证布局，展示验证状态、限流与服务端错误。
- `/workspaces`：我的画布卡片/列表、最近更新、任务统计、新建与管理入口。
- `/canvas/:workspaceId`：复用现有 `App.vue` 画布能力，增加账户摘要、余额/会员入口；保留节点、连线、快捷键、撤销、主题、视口虚拟化和 1280×720 视频约束。
- `/account`：账户资料、邮箱状态、会员等级与到期时间、钱包余额/冻结积分、每日用量、积分流水、订单记录。
- `/account/billing`：三档会员与积分包、微信/支付宝/Mock 下单、二维码或跳转支付、订单轮询与到账反馈。
- `/account/tokens`：创建、设置过期时间、吊销个人 MCP Token；明文仅创建成功时展示一次。
- `/admin`：用户状态/角色/会员管理、套餐与积分商品配置、用量与行为日志、订单、MQ 死信查看和重投。
- 未验证用户可进入个人页面和画布，但生成/充值按钮显示明确验证引导；越权路由由前端守卫和后端授权双重拦截。
- 切换账号或退出时断开 WebSocket、取消轮询、清空内存画布状态，本地缓存按用户命名空间隔离。

### 3. UI 设计交付

新增 `docs/ui-mockup-membership.html` 作为 v1.0 自包含设计稿，不修改原有 `docs/ui-mockup.html`，与真实前端共用设计语言：延续暗色创作台、紫色主色和现有浅色主题，补齐认证、画布首页、会员购买、账户、Token、后台、空态/加载/错误/支付中的桌面与窄屏规格。同步更新实际组件与全局样式，不引入与业务无关的图片或组件库。

## 二、数据库与迁移

### 1. 迁移机制

在 `server/pom.xml` 引入与 JDK 17、Spring Boot 3.4.5、MySQL 5.7 兼容的 Flyway 版本，采用 H2/MySQL 分离脚本：

- 将现有 `db/schema-h2.sql`、`db/schema-mysql.sql` 固化为 V1 基线；新增 V2 多用户会员制迁移。
- 新库执行 V1+V2；已有库启用 baseline 后只执行 V2。关闭原 `spring.sql.init` 重放方式，避免 Flyway 与初始化脚本互相抢建表。
- MySQL 脚本不使用 5.7 不支持的 `ADD/DROP IF NOT EXISTS`；保留现有 H2 MySQL 兼容模式。
- V2 先加可空 `user_id`，一次性初始化管理员并回填全部旧数据，校验后再设非空、组合唯一索引；保留旧文件路径和 workspace 1。
- 旧全局 MCP Token 一次性导入为旧管理员 Token，之后只走个人 Token 表；旧 Session 强制重新登录。

### 2. 核心表

- `app_user`：用户名、规范化邮箱、BCrypt 密码、角色、状态、邮箱验证时间、当前会员及到期时间、时间戳。
- `auth_token`：邮箱验证/找回密码用途、Token 哈希、过期与使用时间；不保存明文。
- `mcp_token`：所属用户、名称、哈希、前缀、过期/吊销/最后使用时间。
- 既有 `workspace/canvas/generation_task/prompt_record/canvas_image/canvas_node/task_image_ref`：全部增加 `user_id`；任务幂等唯一键改为 `(user_id, idem_key)`，供应商任务号仍保持唯一。
- `member_plan`：三档权益、价格、时长、日额度、个人并发、最高分辨率、调度权重、启用状态。
- `credit_package`：积分商品名称、金额分、积分数、启用状态与排序。
- `wallet`：可用积分、冻结积分、`version`；余额更新使用带余额条件的原子 SQL。
- `credit_ledger`：可用/冻结变动、变动后余额、业务类型、业务号、状态和失败原因；`(user_id, type, biz_id)` 唯一保证只结算一次，失败扣费尝试也留痕。
- `payment_order`：商户订单号、用户、商品类型与快照、金额分、渠道、状态、第三方交易号、过期时间、版本。
- `payment_notify_log`：通知摘要、验签结果、处理结果和 payload 哈希，用于排障且不记录密钥。
- `usage_counter`：用户、日/小时周期、调用与积分数；组合唯一键和原子更新支撑配额。
- `audit_log`：用户行为、目标类型/ID、IP、时间和非敏感详情；不记录密码、完整 Token 或支付密钥。
- `event_outbox` / `event_inbox`：事件 ID、聚合与用户、类型、载荷、状态、重试次数、可执行时间、死信原因；消费幂等。

## 三、后端实施

### 1. 认证、用户上下文与数据隔离

关键改造：`SecurityConfig.java`、`AuthController.java`、`McpAuthenticationFilter.java`、全部 domain/mapper、`WorkspaceService.java`、`TaskService.java`、`CanvasNodeService.java` 和各 Controller/MCP Tools。

- 用数据库 `UserDetailsService` 替换 `InMemoryUserDetailsManager`，保留 BCrypt、Session、CSRF、现有登录 IP 渐进限流和 Redis Session 可选能力。
- 新增 auth/user 模块：注册、验证、重发、找回密码、当前账户、管理员初始化与角色提升；公开接口做参数校验、频率限制和统一防账号枚举响应。
- 建立 `CurrentUser`/`UserContext`，在 REST、MCP、WebSocket 中统一解析用户 ID；异步任务显式传递 userId，不能依赖请求线程上下文。
- 配置 MyBatis-Plus 租户拦截器自动为业务 Mapper 附加 `user_id` 并自动填充；认证、迁移、支付回调、Outbox、调度等系统查询使用明确的系统级 Mapper/受控忽略，不做全局放行。
- 在服务边界保留 workspace/task/image/node 的归属校验，跨用户访问统一 404；所有关联资源必须属于同一用户和 workspace。README 所述 `OwnershipAspect` 用于集中声明式校验，但不以 AOP 代替 SQL 租户过滤。
- 生成和充值入口统一检查邮箱验证、账号状态与会员模型分辨率权益。

### 2. 钱包、配额与任务状态

关键改造：`TaskDispatcher.java`、`TaskStatus.java`、`TaskService.java`、`AiService.java`，新增 member/billing/quota 模块。

- 新增 `WalletService.reserve/capture/release`，在同一事务内写钱包与不可变流水；使用原子余额条件和业务唯一键，防止并发负余额、重复扣费、重复退款。
- 为每次生成尝试分配 billingOperationId；视频、异步图片和同步文本调用使用同一计费模板。重试复用有效冻结或显式释放后重新冻结，不重复收费。
- `TaskStatus` 增加 `INSUFFICIENT_BALANCE`、`QUOTA_EXCEEDED`，前端展示差异化原因和充值/额度恢复入口；普通供应商失败仍走 `FAILED`，平台限流仍保留排队重试。
- 个人并发与现有 provider/model、4K 平台并发组成双重闸门；个人/平台槽满保持 `QUEUED`，每日/小时额度耗尽才进入 `QUOTA_EXCEEDED`。
- 保留状态 CAS、`SUBMIT_UNKNOWN`、退避、分布式锁与画布 version 乐观锁。按会员权重对用户做 deficit round-robin，避免高并发用户长期饿死低等级用户。
- 每日/小时计数与冻结/释放保持一致；日额度在次日恢复后由用户重试，不自动重复提交结果未知的任务。
- 记录生成、登录、支付、Token、管理员调整等审计元数据，并增加按用户 API 限流；单实例本地执行，多实例启用 Redis 时共享限流状态。

### 3. MQ 解耦与调度恢复

- 任务写入、计费冻结、Outbox 写入同事务提交；本地 `mq=db` 由调度消费者认领 Outbox 后进入现有提交流程，重启可恢复。
- `mq=rabbitmq` 时由事务后的 Outbox relay 发布 RabbitMQ，消费端复用同一个幂等处理器；消费成功才确认，按配置重试，超限进入死信表/队列。
- 增加 Admin 死信列表与受权限保护的手动重投；保留供应商状态轮询、Redis 调度锁及 Redis 故障时本轮暂停策略。
- 单实例仍无需 Redis/RabbitMQ 即可完整运行；不引入 RocketMQ/Kafka 多套实现，文档说明后续扩展接口即可。

### 4. WebSocket、MCP、文件与存储隔离

关键改造：`CanvasWebSocketHandler.java`、`CanvasSocketRegistry.java`、`CanvasEvent.java`、Redis relay/subscriber、`AssetService.java` 和本地文件访问配置。

- WebSocket 握手从 Session 获取用户，验证 workspace 归属后注册 `(userId, workspaceId)`；广播和 Redis 事件都携带用户维度，跨用户连接不接收事件。
- MCP Bearer Token 改为查哈希、过期与吊销状态，认证主体映射真实用户；所有 MCP 工具沿用同一归属校验、幂等、计费和配额逻辑。
- CLI 默认 workspace 不再假定全局 1；服务端仅允许访问当前用户 workspace。
- 新上传与转存对象键使用 `{userId}/images|videos/...`；旧资源保留原路径但按记录的 userId 校验归属。
- 本地 `/files/**` 由静态公开映射改为鉴权后的资源访问；私有 MinIO/COS/OSS 仅在资源归属校验后生成短期签名 URL。
- 继续保持“第三方产物必须转存自有存储”，转存失败不得标记成功或保存第三方 URL。

### 5. IJPay 支付闭环

在 `server/pom.xml` 使用 IJPay 2.9.7，新增 payment 模块与配置：

- 统一 `PaymentChannel`：`mock`、`wechat-native`（微信支付 V3）、`alipay-page`（支付宝电脑网站支付）。
- 创建订单时读取启用商品并保存价格/积分/会员快照，返回二维码内容或支付跳转信息；前端轮询本人订单状态，提供取消/关闭未支付订单。
- 微信/支付宝回调端点允许匿名访问但豁免范围最小化，并豁免 CSRF；必须依次验签、校验商户/订单/金额、CAS 更新订单，再在同一事务完成钱包或会员入账。
- 重复通知、乱序通知和重复请求保持幂等；金额不符、已关闭后到账、验签失败进入明确异常记录与人工核对，不直接增加余额。
- 密钥、证书、商户号、回调地址均通过环境变量注入；Mock 支付与开发到账按钮仅 local profile 装配。

## 七、验证

### 自动化与构建

- 设置 `JAVA_HOME=C:\Program Files\Java\jdk-17` 后，在 `server` 执行 `mvn test`；若后端正在运行，先停止服务，禁止直接覆盖运行中的 JAR。
- 在 `web` 执行 `npm run build`；检查 CLI 语法与本地帮助/账户命令。
- 保留并扩展现有 `WorkspaceServiceTest`、`PromptRecordServiceTest`、`ImageReferencePromptTest`、`ModelCatalogTest`，新增 auth、tenant、wallet、payment、outbox、quota、WebSocket/MCP 测试。

### 核心验收

- 全新 H2 和模拟旧 H2 均能升级；旧数据只归管理员；MySQL 5.7 脚本单独验证，无实例时明确标注未实测。
- 两个用户互访对方 workspace、任务、图片、节点、提示词、文件、WS、MCP 均为 404/握手拒绝；列表不串数据，WS 不串消息。
- 注册、开发验证链接、Token 过期/复用、重发、找回密码、禁用账号和未验证生成限制全部通过。
- 并发生成不出现负余额或超个人并发；成功只扣一次，失败/取消退回一次，重复重试和调度恢复不重复冻结，`SUBMIT_UNKNOWN` 不自动重扣。
