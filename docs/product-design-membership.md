# 产品设计：多用户会员制（v1.0）

> 本文描述 `feature/multi-user-membership` 分支的产品形态。单用户版设计见 `docs/product-design.md`，两份文档并存。

## 1. 产品目标

把单用户画布升级为面向创作者的 SaaS 工作台：每个用户拥有独立的画布、素材和生成任务，通过会员权益与积分消费使用 AI 能力；管理员负责用户、商品和风控，而不是替用户操作画布。

核心闭环：注册 → 验证邮箱 → 获得会员与积分 → 创建画布 → 生成脚本/图片/视频 → 积分结算 → 充值或升级会员。

## 2. 角色

| 角色 | 能力 |
| --- | --- |
| 游客 | 注册、登录、找回密码 |
| 用户 USER | 管理自己的画布、生成任务、查看积分与订单、创建个人 MCP Token |
| 管理员 ADMIN | 用户状态/角色/会员调整、会员与积分商品配置、订单、审计、Outbox 死信重投；默认不浏览用户私人画布内容 |

管理员由已有用户提升；管理员账号同样以普通用户身份拥有自己的画布，跨用户访问一律按 404 处理。

## 3. 账户与安全

- 注册字段：用户名（3-32 位字母/数字/下划线）、邮箱、密码（8-72 位）。用户名与邮箱均唯一且不区分大小写。
- 邮箱验证：注册后可登录并管理画布，但**验证邮箱前不能 AI 生成或充值**。本地 `log` 模式在注册响应与日志中返回开发验证链接；SMTP 模式发送邮件。验证链接 24 小时有效，一次性使用。
- 找回密码：30 分钟有效的一次性链接；重置后旧链接失效。
- 登录：数据库 BCrypt 校验 + Session Cookie + CSRF；保留按 IP 的渐进式登录限流与封禁。
- 登出或切换账号：前端断开 WebSocket、取消轮询、清空内存画布与按用户隔离的本地缓存。

## 4. 会员与积分

### 4.1 三档会员（可在管理后台修改）

| 档位 | 价格 | 有效期 | 每日额度 | 个人并发 | 最高分辨率 | 调度权重 |
| --- | --- | --- | --- | --- | --- | --- |
| 免费版 FREE | ¥0 | 长期 | 50 积分 | 1 | 720P | 1 |
| 专业版 PRO | ¥29.9 | 30 天 | 500 积分 | 2 | 1080P | 3 |
| 工作室版 STUDIO | ¥99.9 | 30 天 | 3000 积分 | 5 | 4K | 6 |

- 会员到期自动回落到免费版；管理员可将用户会员延长到指定日期。
- 清晰度按会员档位限制：请求高于档位时自动降到该档最高分辨率。
- 每日额度按“成功生成消耗的积分”累计；额度耗尽返回 `QUOTA_EXCEEDED`，次日恢复。
- 个人并发按会员档位限制；个人或平台槽位已满时任务保持 `QUEUED`，不直接失败。

### 4.2 积分

- 积分来源：充值、会员购买附赠（如需）、管理员调整、初始赠送。
- 积分用途：视频、图片、文本生成。价格按 `provider/model` 配置，视频按 5 秒基准价按时长折算，图片按张数计算，文本使用固定单价。
- 计费规则：
  1. 提交生成前按当前模型与参数估价并**冻结**积分；
  2. 生成成功**实扣**并计入当日额度；
  3. 明确失败、超时、取消**退回**冻结积分；
  4. 提交结果未知（`SUBMIT_UNKNOWN`）保持冻结并等待人工核对，不自动重扣；
  5. 积分不足写入零变动失败流水并返回 `INSUFFICIENT_BALANCE`。
- 所有流水不可变，`(user_id, type, biz_id)` 唯一，保证重复请求或重试不会二次扣费。

## 5. 画布与生成

- 登录后进入「我的画布」：卡片展示名称、最近更新、镜头/图片数量、进行中任务；支持新建、重命名、复制、删除。每个用户至少保留一个画布。
- 画布内保留现有能力：脚本/文本/AI 图片/视频节点、连线、@图片引用、快捷键、撤销、一键排列、主题、视口虚拟化、视频按需加载、1280×720 视频节点。
- 复制画布只创建草稿任务，不自动进入生成队列。
- 生成按钮在邮箱未验证、余额不足、额度耗尽时给出明确引导；排队中显示排队原因，不伪装为失败。

## 6. 订单与支付

- 商品：三档会员与积分包（100 / 500 / 2000 积分）。
- 下单时保存商品快照（名称、价格、积分、会员时长），后续后台改价不影响已创建订单。
- 订单状态：`PENDING → PAYING → PAID`，未支付超时或用户取消进入 `CLOSED`。
- 渠道：`mock`（仅本地）、`wechat`（微信支付 V3 Native 二维码）、`alipay`（电脑网站支付表单）。
- 到账规则：验签 → 校验商户/订单/金额 → CAS 更新订单 → 钱包充值或会员升级，同一事务完成；重复/乱序通知幂等；金额不符、关单后到账、验签失败进入人工核对。
- 前端在支付页轮询本人订单状态，展示待支付/支付中/成功/失败/关单。

## 7. 个人 MCP Token

- 每个用户可创建多个 Token，设置名称与过期时间；明文仅在创建成功时展示一次。
- Token 仅保存 SHA-256 哈希，可随时吊销；调用 MCP 时映射为真实用户，沿用同一归属校验、幂等、计费与配额规则。
- 旧的全局 `MCP_API_TOKEN` 仅兼容映射到管理员，不作为长期方案。

## 8. 管理后台

- 用户：搜索、禁用/启用、角色调整、会员档位与时长调整。
- 会员档位：名称、描述、价格、有效期、日额度、并发、最高分辨率、调度权重、启用状态、排序。
- 积分商品：编码、名称、积分数、价格、启用、排序。
- 订单、审计日志、Outbox 死信列表与重投。
- 敏感操作写入审计；页面与接口均校验 `ROLE_ADMIN`。

## 9. 状态与提示

| 状态/错误码 | 用户提示 |
| --- | --- |
| `EMAIL_NOT_VERIFIED` | 请先完成邮箱验证后再生成/充值 |
| `INSUFFICIENT_BALANCE` | 积分不足，请先充值 |
| `QUOTA_EXCEEDED` | 今日额度已用完，请升级会员或明日再试 |
| `ACCOUNT_DISABLED` | 账号已被禁用，请联系管理员 |
| `QUEUED`（排队） | 当前并发已满，任务排队中 |
| `SUBMIT_UNKNOWN` | 提交结果未知，已冻结积分并等待核对 |
| 支付 `CLOSED` | 订单已关闭，请重新下单 |

## 10. 验收口径

1. 两个账号的画布、任务、图片、节点、提示词、文件、WebSocket、MCP 互不可见（越权 404/拒绝握手）。
2. 注册 → 开发验证链接 → 验证 → 登录 → Mock 充值 → 生成 → 结算 → 刷新恢复 → 第二账号隔离全流程可完成。
3. 并发生成不出现负余额或超个人并发；成功只扣一次，失败/取消退回一次，重复回调只到账一次。
4. 会员到期回落、清晰度限制、每日额度、双重并发与新任务状态符合设计。
5. 单实例无需 Redis、RabbitMQ、SMTP、支付商户即可完整演示；真实外部服务仅在配置凭据后追加验收。
