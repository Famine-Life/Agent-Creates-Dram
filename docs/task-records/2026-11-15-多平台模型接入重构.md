# 多平台模型接入重构

日期：2026-11-15

## 需求

原有配置按「供应商」分组且文本、图片、视频各自维护，接入的都是字节体系、共用同一个 `base-url`。后续需要接入阿里云百炼、OpenAI 等平台，因此要求：

- 平台（provider）与模型（model）解耦：平台只管地址、密钥、协议；模型声明能力与参数范围。
- 统一用 `provider/model` 复合标识引用模型，文本、图片、视频三类能力使用同一套结构。
- 视频不能再把 `seedance` / `seedance-fast` 当模型 ID 硬编码在前端与任务表。
- 未配置 `api-key` 的平台不出现在 `/api/meta` 与前端下拉中；全部未配置时继续回落 mock。
- 兼容存量 `provider=seedance` / `seedance-fast` 的任务轮询。

## 改动清单

- 配置层
  - `AiProperties` 重写为 `aigc.ai`：`default-provider`、`defaults.{text,image,video}`、`providers.<平台>.{label,base-url,api-key,protocols,text-models,image-models,video-models}`。
  - 删除 `ProviderProperties` 与 `aigc.provider.*`；mock 作为普通平台（`protocols` 为 `mock` / `mock-video`）。
  - 视频模型支持 `ratios / resolutions / durations / default-ratio / default-duration / watermark`。
  - `application.yml` 内置 `ark`、`openai`、`dashscope`、`mock` 四个平台；`openai` / `dashscope` 填入密钥即自动启用。
  - `application-local.yml` 只覆盖 `aigc.ai.providers.ark.api-key`，模型清单仍以 `application.yml` 为唯一来源。
- 模型目录
  - 新增 `ModelRef`（解析 `provider/model`）与 `ModelCatalog`：
    - 按能力解析默认模型；默认值不可用时回退首个可用模型。
    - 支持裸模型 ID 与旧别名 `seedance` / `seedance-fast` / `mock`。
    - 未配置密钥的平台在解析和列表中都视为不可用；有真实平台时列表不再混入 mock。
    - `resolveVideoTask` / `taskKey` 兼容存量任务字段组合。
- AI 文本 / 图片
  - `AiService` 改为按解析结果调用：文本 `openai-compatible`，图片 `ark-image` / `openai-image`，mock 走原演示逻辑。
  - `RestClient` 按 `base-url` 缓存，同一适配器可服务多个平台。
- 视频
  - `VideoProvider` 的 `poll` / `cancel` 增加 `VideoContext`，适配器不再读取全局配置。
  - 新增 `ArkVideoProvider`（`ark-video`），删除 `SeedanceVideoProvider` / `SeedanceFastVideoProvider`；`MockVideoProvider` 改为 `mock-video`。
  - `ProviderRegistry` 按协议注册，未知协议明确报错，不再静默回退 mock。
  - 任务表语义改为 `provider=平台标识`、`model=真实模型 ID`；`TaskDispatcher` 提交 / 轮询 / 取消都通过 `ModelCatalog` 解析。
  - `TaskService` 的比例、清晰度、时长改为按所选模型的能力白名单校验与兜底。
- 接口与前端
  - `/api/meta` 返回 `defaults.{text,image,video}`、`providerLabel` 与带 `provider` / `providerLabel` 的 `textModels` / `imageModels` / `videoModels`。
  - `TaskNode` 新增 `modelKey`，前端下拉使用复合标识，任务展示仍显示真实模型 ID。
  - 脚本节点、AI 图片节点、镜头节点改为读取 `/api/meta`，删除硬编码模型与清晰度列表；`PromptEditor` 用 `optgroup` 按平台分组。
  - CLI 的 `--model` 说明改为 `provider/model`。
- 测试与文档
  - 新增 `ModelCatalogTest` 覆盖默认解析、复合 / 裸模型、未启用平台、旧别名、能力参数。
  - `Seedance2LiveTest` 改为通过 `ModelCatalog` 构造 `VideoContext`。
  - 更新 `docs/architecture.md` 的多平台接入说明与配置表。

## 验证结果

- 后端测试：10 个通过，1 个跳过（`Seedance2LiveTest` 实时调用默认跳过），0 失败。
- 后端打包：`mvn -DskipTests package` 成功。
- 前端 `npm run build` 成功。
- 使用 `local` Profile 启动后登录访问 `/api/meta`：
  - `provider=ark`、`providerLabel=火山方舟`，默认模型分别为 `ark/doubao-seed-evolving`、`ark/doubao-seedream-4-0-20260415`、`ark/doubao-seedance-2-0-260128`；
  - `textModels` 6 个、`imageModels` 2 个、`videoModels` 2 个，均仅含方舟；
  - `openai` / `dashscope` 因未配置密钥、`mock` 因存在真实平台，均未出现在下拉中，说明平台合并与可见性过滤生效。
- 传入 `ark/not-exist` 调用提示词优化返回 400，模型白名单校验正常。
- 真实文本调用已到达方舟，但当日 Ark 返回 `429 RequestBurstTooFast`（请求突增保护），未取得 200；请求地址、鉴权头与请求体结构已由错误响应确认可用。

## 影响面与兼容性

- 旧任务 `provider=seedance` / `seedance-fast` 在提交、轮询、取消和展示时自动映射到 `ark/doubao-seedance-2-0-260128` / `ark/doubao-seedance-2-0-fast-260128`。
- 未传 `model` 的 REST / MCP / CLI 请求继续使用默认模型；裸模型 ID 仍可解析。
- 任务表未改结构：`provider` 存平台标识（长度足够 ark / openai / dashscope），`model` 存真实模型 ID。
- `mock` 在存在真实平台时从下拉隐藏，但显式传 `mock/mock-video` 或旧值 `mock` 仍可解析。
- `AIGC_PROVIDER`、`ARK_MODEL`、`ARK_FAST_MODEL`、`AIGC_TEXT_MODEL` 等旧环境变量不再生效，分别由 `AIGC_VIDEO_MODEL`、`AIGC_AI_PROVIDER` 与平台配置替代。

## 遗留问题

- 阿里云百炼当前复用 `openai-compatible` 文本协议；图片 / 视频若使用 DashScope 私有协议、Kling 等，需要新增对应适配器（配置结构已预留 `protocols`）。
- 前端暂未提供「平台」独立筛选，仅通过下拉分组展示。
- Seedream / Seedance 真实出片仍需在额度可用时验证返回结构。
- Ark 的 429 需要在调用侧增加重试或限流，当前统一按 500 返回给前端。
