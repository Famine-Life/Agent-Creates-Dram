# 文本与图片模型接入

日期：2026-11-15

## 需求

在画布内接入以下模型，并支持生成时切换：

- 文本模型（脚本生成 / 提示词优化）：
  - `doubao-seed-evolving`
  - `doubao-seed-2-1-pro-260915`
  - `doubao-seed-2-1-lite-260915`
  - `deepseek-v4-1-flash-261017`
  - `deepseek-v4-1-flash-economy-261017`
  - `glm-5-3-flash-260828`
- 图片模型：
  - `doubao-seedream-5-5-261028`
  - `doubao-seedream-4-0-20260415`

默认文本模型为 `doubao-seed-evolving`，默认图片模型为 `doubao-seedream-4-0-20260415`。

## 改动清单

- 后端 `AiProperties` 新增 `textModels` / `imageModels` 白名单与 `resolveTextModel` / `resolveImageModel` 校验；默认文本、图片模型按需求调整。
- `application.yml` 增加两组模型清单；`aigc.ai.api-key` 在未配置 `ARK_API_KEY` 时复用 `aigc.provider.seedance.api-key`，避免 local 配置重复维护。
- `application-local.yml`（本地私有、不入库）同步新增 `aigc.ai` 配置块，包含默认模型与两组模型清单，密钥同样复用视频供应商配置。
- `AiService` 的 `generateScript` / `optimizePrompt` / `generateImage` 增加 `model` 参数，调用前按白名单校验，未传时使用默认模型。
- 文生图尺寸由 `1024x576` 调整为 `1280x720`，与 Seedream 4.0 / 5.5 及画布 16:9 比例保持一致。
- `GenerateRequest` 增加 `model` 字段；`CanvasController` 的脚本生成、图片生成、提示词优化接口透传模型。
- `CanvasNodeService` 生成脚本 / 图片时把模型传给 `AiService`。
- `/api/meta` 返回 `textModels`、`imageModels`，供前端渲染下拉。
- 前端脚本节点、AI 图片节点在提示词编辑器底部新增模型下拉；`PromptEditor` 在没有参数面板时也支持展示模型下拉。
- 新增 `AiPropertiesTest` 覆盖默认模型、白名单校验与非法模型拒绝。
- 同步更新 `docs/architecture.md` 配置表与节点内交互说明。

## 验证结果

- 后端测试：`AiPropertiesTest` 4 个、`LocalAssetStorageTest` 2 个、`PromptRecordServiceTest` 1 个全部通过；`Seedance2LiveTest` 按配置跳过。合计 8 个，0 失败，1 跳过。
- 后端打包：`mvn package -DskipTests` 成功。
- 前端 `npm run build` 成功，102 个模块，产物正常生成。
- 使用 `local` Profile 启动后端后，登录访问 `/api/meta` 返回：
  - `aiMock=false`，说明 `aigc.ai.api-key` 已复用视频供应商密钥；
  - `scriptModel=doubao-seed-evolving`、`imageModel=doubao-seedream-4-0-20260415`；
  - `textModels` 6 个、`imageModels` 2 个，模型清单完整。
- 真实文本模型验证：`POST /api/canvas/1/ai/prompt/optimize` 使用 `doubao-seed-evolving` 返回 200，确认 Ark 密钥、模型 ID 与请求结构可用。
- 图片生成未执行真实调用，避免消耗额度；Seedream 5.5 / 4.0 的权限与返回结构需在画布内首次使用时确认。

## 影响面与兼容性

- 未传 `model` 的旧请求继续使用默认模型，REST / MCP / CLI 调用不受影响。
- 传入了不在白名单内的模型会返回 400「不支持的文本模型 / 图片模型」。
- 前端模型选择为节点内临时状态，刷新页面后回到默认模型；未新增数据库字段。
- mock 模式下不展示模型下拉，仍使用原有 mock 脚本 / 图片。

## 遗留问题

- 需要用户提供 Ark API Key 才能实际验证 8 个模型的权限与返回结构；本地可通过 `ARK_API_KEY` 或 `application-local.yml` 中视频供应商密钥复用。
- Seedream 5.5 / 4.0 的具体尺寸、参考图与返回字段如与现有 `images/generations` 请求存在差异，需要在真实调用后按官方文档微调。
