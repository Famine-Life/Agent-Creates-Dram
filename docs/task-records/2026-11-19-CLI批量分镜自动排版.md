# CLI 批量分镜自动排版

## 需求

使用 CLI `storyboard` 批量生成节点时要考虑排版，避免新镜头/参考图堆叠或与已有节点重叠。

## 实现

- `cli/aigc.mjs`
  - 新增 `arrangeStoryboardLayout(workspaceId, created, columns = 4)`：批量创建镜头后拉取画布全量状态，计算新节点坐标并通过 `PUT /api/canvas/{id}/snapshot`（`positions` + `baseVersion`）写回，409 冲突自动重试一次。
  - 排版规则：
    - 同组镜头接在该组最右侧已有镜头之后，横向排列（列距 28）；**每行最多 N 个（`--columns`，默认 4，1-12），超出自动折行**：接已有分组时若当前行已满则直接折行，折行后回到本组最左侧、在组内容下方另起一行（行距为镜头块高 450 + 20）；
    - 新分组整体放到现有内容下方（组间距 56），空画布从 (72, 96) 开始；
    - 参考图跟随所属镜头的实际坐标，放在镜头下方（+240）并横向错开；
    - 镜头占位高度按 220+230 计算，为提示词编辑器与参考图预留空间；
    - 已有坐标的节点（含幂等命中的旧镜头）不移动，只参与碰撞占位；候选位置与已有节点重叠时向右步进避让。
  - `storyboard` 输出排版结果；排版保存失败只提示，不影响已创建的镜头；`--json` 输出保持原有任务数组结构不变。
  - 帮助信息补充「创建后自动排版并保存快照」。
- `docs/architecture.md`：CLI 章节补充自动排版规则。

## 验证

- `node --check cli/aigc.mjs`：通过。
- 用独立脚本（临时目录，不进入仓库）提取排版函数、打桩 API 验证 5 个场景全部通过：
  1. 空画布同组 3 个镜头 → (72,96) / (420,96) / (768,96)；
  2. 同组新镜头接在最右侧，旧镜头坐标不变，viewport 等快照字段保留；
  3. 新分组排到现有内容下方（y=602）；
  4. 参考图落在所属镜头下方 (72,336)；
  5. 幂等命中的旧镜头不移动，新镜头接在其右侧。
- 测试中发现并修复：`Number(null) === 0` 导致无坐标图片被误判为已定位，`layoutPos` 现在显式排除 `x/y == null`。
- 折行场景打桩验证全部通过：空画布 6 个镜头每行 4 个（第二行回到最左 y=566）、已有满行直接折行、已有半行先补足再折行、`--columns 2` 自定义、折行后参考图仍跟随所属镜头、新组排在折行内容之下。
- 未在真实画布上执行批量生成，避免产生额外节点。
