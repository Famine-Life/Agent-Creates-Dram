# 2026-11-14 CLI 命令行工具

## 1. 需求背景

在讨论「REST 和 CLI 是不是一个意思」之后，用户确认希望系统具备 CLI 能力，并选择「Node CLI 脚本封装现有 REST」这一形态：不新增后端依赖，用命令行完成登录、推送提示词、查看画布与素材、上传图片等操作。

## 2. 改动清单

### 新增

- `cli/aigc.mjs`
  - 零依赖（Node.js 16+ 内置 `http/https/fs/os/path`），不引入 npm 包；
  - 命令：`login`、`logout`、`canvas`（别名 `status`）、`assets`、`push`、`storyboard`、`upload`、`rm`、`rm-image`、`help`；
  - 通用参数：`--url`、`--workspace`、`--json`；
  - 登录态保存到 `~/.aigc-cli/session.json`（Cookie、CSRF Token、服务地址、用户名）；
  - 写操作自动请求 `/api/auth/csrf` 并携带 `X-XSRF-TOKEN`；登录后 Session 轮换会重新取 Token；
  - `upload` 手写 multipart 请求体，兼容 Node 16（无全局 `FormData`/`fetch`）；
  - `assets` 按 `source` 区分生成图片与上传图片，并列出已生成视频。

### 文档

- `docs/architecture.md`：新增 4.12 CLI 客户端（`cli/`）。

## 3. 验证方式与结果

后端 8080 正常运行，使用管理员账号本机验证：

- `login`：输出「已登录：admin @ http://localhost:8080」；
- `canvas`：正确输出画布版本、镜头 5 个、图片 4 张（上传 4 / 生成 0）及各镜头状态；
- `assets --type upload`：列出 4 张上传图片的 ID、名称与访问地址；
- `push`：创建镜头 `#257`，状态 `QUEUED`，随后 `rm --id 257` 删除成功；
- `upload`：上传图片生成节点 `#161`，随后 `rm-image --id 161` 删除成功；
- 未登录状态执行写命令会提示先 `login`；401 时提示重新登录。

## 4. 影响面与兼容性

- 纯新增工具，未修改任何后端代码、数据库或前端构建；
- 复用现有 Session + CSRF 鉴权，没有扩大 MCP Token 的权限范围；
- Node 16 与 18+ 均可运行，无第三方依赖；
- 会话文件位于用户主目录，不进仓库。

## 5. 遗留问题 / 下一步

- 暂不支持 `watch` 轮询生成进度；如需可基于 `GET /api/canvas/{id}` 增加；
- 批量分镜文件格式为 JSON 数组或 `{ "shots": [...] }`，尚未提供模板导出命令；
- 如需无交互鉴权（CI/脚本），可后续新增独立的 CLI Token 并放行 `/api/**`。
