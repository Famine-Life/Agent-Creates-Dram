# 生成任务并发与队列保护

日期：2026-11-16

## 需求背景

用户要求：“按照优化建议修改，记得增加企业/个人账号标识设置在yml配置，默认是企业”。此前检查发现视频任务调度未在本地按模型额度限流，方舟 queued 被显示为运行中，提交错误会直接失败；图片生成线程池使用无界队列。

## 改动清单

- server/src/main/java/com/aigc/video/task/TaskDispatcher.java：按模型与 4K/非 4K 对在途任务计数；仅在本地容量允许时提交；识别方舟排队状态；429 遵循 Retry-After 并退避，最多自动重试 8 次；5xx/网络中断及崩溃恢复时转为 SUBMIT_UNKNOWN，避免盲目重复提交；记录活跃占用和提交情况。
- TaskStatus.java、ArkVideoProvider.java、PollResult.java：增加 SUBMITTING、PROVIDER_QUEUED、SUBMIT_UNKNOWN 状态与方舟排队映射。
- DispatchLock.java：Redis 锁不可用时暂停调度，避免多实例的容量计数失效。
- TaskService.java、ApiExceptionHandler.java、TooManyRequestsException.java：限制本地待提交任务队列，满时返回 HTTP 429；重试/重新生成同样检查容量。
- CanvasNodeService.java：将图片生成改为有界工作队列；队列满时返回 HTTP 429，并显示本地排队状态。
- application.yml：新增 AIGC_ACCOUNT_TYPE，默认 enterprise；并发额度、重试上限、队列容量和图片线程池参数均可配置。
- web/src/store/canvas.js、web/src/components/ShotNode.vue、ShotInspector.vue、Sidebar.vue、ImageGenNode.vue：区分本地排队、供应商排队、提交待确认和图片本地排队状态；未知结果重试前提示核对平台控制台。
- docs/architecture.md、docs/volcengine-api-concurrency.md：同步任务状态、配置及队列说明。

## 影响面与兼容性

- 任务状态只新增字符串状态，不新增数据库列；既有状态数据继续兼容。
- 默认 enterprise 使用普通视频并发 10、4K 并发 1；设置 AIGC_ACCOUNT_TYPE=personal 使用普通视频并发 3、4K 并发 1。此为本地调度闸门，需按账号和方舟控制台额度调整。
- Redis 多实例锁异常时调度暂停；未开启 Redis 时按单实例运行。
- 网络提交结果不确定会进入 SUBMIT_UNKNOWN，需用户核对平台控制台后手动重试；界面已增加确认提示。
- 图片队列仅限制本地工作线程/排队量，方舟 IPM 仍由平台模型额度控制。

## 遗留问题 / 下一步

- 多实例全局额度统计依赖共享 Redis 调度锁；Redis 故障会暂停视频提交，恢复后自动继续。
- 图片 IPM 因模型/账号不同，仍需在方舟控制台查看实际额度；当前实现使用本地有界队列，不模拟平台分钟额度。
- 队列容量检查是数据库计数式软上限，高并发同时创建时可能短暂超过配置值。
