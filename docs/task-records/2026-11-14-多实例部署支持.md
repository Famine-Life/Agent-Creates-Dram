# 2026-11-14 多实例部署支持

## 1. 需求背景

上一版安全改造后遗留两条多实例问题：调度是进程内 `@Scheduled`，多个实例会同时扫表；网页 Session 存在实例内存，负载均衡到另一台实例就会掉登录。本次补上 Redis 调度分布式锁与可选 Redis Session，同时保持「默认单机、无 Redis 也能完整运行」。

## 2. 改动清单

| 文件 | 改动 |
| --- | --- |
| `server/pom.xml` | 新增 `org.springframework.session:spring-session-data-redis` |
| `task/DispatchLock.java` | 新增调度锁：`SET NX` + 120s TTL 抢锁，Lua 校验 token 后释放；Redis 异常时本轮放行并打 WARN |
| `task/TaskDispatcher.java` | `tick()` 先取锁，取不到直接返回；`submitQueued` / `pollRunning` 仍在 try/finally 内释放锁 |
| `config/SessionConfig.java` | 新增：`aigc.session.redis-enabled=true` 时 `@EnableRedisHttpSession(redisNamespace = "aigc:session")` |
| `resources/application.yml` | 新增 `aigc.session.redis-enabled: ${AIGC_SESSION_REDIS_ENABLED:false}`；补充 `realtime.redis-enabled` 同时控制调度锁的说明 |

## 3. 使用方式

单机（默认，无需 Redis）：

```powershell
java -jar aigc-video-server-0.1.0.jar
```

多实例（各实例需连接同一 Redis 与同一 MySQL）：

```powershell
$env:AIGC_REDIS_ENABLED='true'          # 画布事件跨实例广播 + 调度分布式锁
$env:AIGC_SESSION_REDIS_ENABLED='true'  # 登录 Session 存 Redis
$env:REDIS_HOST='127.0.0.1'
$env:REDIS_PORT='6379'
$env:REDIS_DATABASE='10'
```

- 调度锁键为 `aigc:dispatch:lock`，锁 TTL 120 秒，任务异常退出不会死锁。
- Session 命名空间为 `aigc:session`，Cookie 仍是 `AIGCSESSION`（沿用 `server.servlet.session.cookie` 的 HttpOnly / SameSite / Secure 配置）。
- 开启 Session Redis 后，Redis 不可用会导致无法登录，需保证 Redis 高可用；MCP 的 SSE 会话仍绑定单实例，多实例需在网关做会话粘滞。

## 4. 验证

环境：本机 Redis（db 10），两个测试实例 8081 / 8082，各自独立的内存 H2，不触碰正式画布数据。

| 项目 | 结果 |
| --- | --- |
| `mvn -DskipTests package`（JDK 17） | PASS |
| 默认配置启动 + 登录 | PASS，Session 仍在实例内存，Redis 无 `aigc:session` 键 |
| 集群配置启动 A/B 两实例 | PASS，`SessionRepositoryFilter` 生效，Redis 出现 `aigc:session:sessions:*` |
| A 实例登录后用同一 Cookie 访问 B 实例 `/api/auth/session` | PASS，返回 `authenticated=true`、`username=admin` |
| 未带 Cookie 访问 B 实例 | PASS，未认证 |
| 模拟其它实例持有 `aigc:dispatch:lock` 后创建镜头 | PASS，任务停留 `QUEUED` 5 秒未被调度 |
| 释放锁后同一任务 | PASS，约 2 秒内提交并最终 `SUCCEEDED` |
| 正式 8080 服务（默认配置）重启后登录与画布 | PASS，原有镜头与参考图数据完整 |

验证脚本与临时 Cookie 文件均放在 `server/target` 下，验证完成后已删除；测试实例已停止。

## 5. 影响面与兼容性

- 默认配置完全不变化：不开启 Redis 时调度锁是直通实现，Session 仍在容器内存，单机无 Redis 可正常登录。
- `AIGC_REDIS_ENABLED=true` 新增了「调度锁」行为：同一时刻只有一个实例扫表，原 Redis 广播逻辑不变。
- `AIGC_SESSION_REDIS_ENABLED` 为新增开关，与广播开关独立，可只开 Session 共享或只开广播。
- 多实例仍需共享数据库（H2 文件库不支持），任务表结构的 CAS / 幂等逻辑保持不变。

## 6. 遗留问题 / 下一步

- 调度锁 TTL 固定 120 秒；若单轮 `tick` 超过该时长（大文件转存），可能出现两个实例短暂并发轮询，仍依赖状态 CAS 兜底，必要时可改为可配置 TTL 或续期。
- MCP SSE 会话未做共享，多实例下需网关会话粘滞。
- Session 序列化使用默认 JDK 序列化，后续如需跨语言或版本兼容可切换 JSON 序列化器。
- 真实多实例压测（MySQL + 多 JVM + 负载均衡）尚未执行。
