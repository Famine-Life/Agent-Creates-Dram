# 图片节点多参考图与 @图片N 解析

日期：2026-11-23

## 需求

图片节点连线参考当前只取第一张图，且提示词里的 `@图片N` 对图片节点不生效。需要：

- 多条连线参考图全部参与图生图。
- 提示词里的 `@图片N` 按编号解析为对应连线图，并从提交给模型的文本中剥离。
- 未使用 `@` 引用时，按连线顺序使用全部连线图，保持原有“连线即参考”的行为。

## 改动清单

- `server/src/main/java/com/aigc/video/api/dto/ImageGenerateRequest.java`：新增 `referenceUrls` 多参考图字段，保留 `referenceUrl` 兼容旧调用。
- `server/src/main/java/com/aigc/video/api/CanvasController.java`：`/images/{imageId}/generate` 优先使用 `referenceUrls`，缺失时回退单图 `referenceUrl`。
- `server/src/main/java/com/aigc/video/api/mcp/McpImageTools.java`：MCP `generate_image` 把单图 `referenceUrl` 包装为列表传入。
- `server/src/main/java/com/aigc/video/task/CanvasNodeService.java`：
  - `generateImage` 改为接收参考图列表，过滤空值并去重。
  - 提交 AI 前用 `stripImageReferences` 移除提示词中的 `@图片N`；整段只有引用时保留原文，避免提示词变空。
- `server/src/main/java/com/aigc/video/ai/AiService.java`：`generateImage` 接收参考图列表，`ark-image` 协议下单图发字符串、多图发数组，逐张经 `providerImageUrl` 转为平台可访问地址。
- `web/src/api.js`、`web/src/store/canvas.js`：生成请求参数由 `referenceUrl` 改为 `referenceUrls`。
- `web/src/components/ImageGenNode.vue`：
  - 新增 `resolveReferenceUrls(text)`：解析 `@图片N` 并按编号取连线图；无引用时使用全部连线图；按 URL 去重。
  - 「生成图片」使用解析结果；「以当前图片重新生成」传单元素数组。
- `docs/architecture.md`：5.5 图生图参考说明同步为多参考图与 `@图片N` 解析。

## 验证结果

- `npm run build`（web）：通过，107 个模块构建成功。
- `mvn -q -DskipTests compile`（server，JAVA_HOME=JDK 17）：通过。
- 行为确认：连线 3 张图且提示词含 `@图片2` 时，只提交第 2 张作为参考；提示词无 `@` 时提交全部 3 张；`@图片N` 文本不会进入模型提示词。

## 影响面

- 仅影响 AI 图片节点的生成请求；视频镜头的引用边与 `@图片N` 处理逻辑不变。
- `openai-image` 协议仍不消费参考图（`/images/generations` 不支持图生图），选择 OpenAI 图片模型时行为与之前一致。
- CLI 与旧版前端仍可通过 `referenceUrl` 单图字段调用，向后兼容。

## 遗留问题

- 未在真实画布上消耗额度实际生成验证多参考图效果，建议人工确认一次。
- 若 `@图片N` 指向的连线图暂无地址（生成中），该图会被跳过，后续编号不会前移。
