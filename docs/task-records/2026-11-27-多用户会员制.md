## 改动清单

### 数据库与迁移

- 引入 Flyway，新增 `server/src/main/resources/db/migration/h2|mysql/V1__baseline.sql`、`V2__multi_user_membership.sql`；删除旧的 `db/schema-h2.sql`、`db/schema-mysql.sql` 与 `spring.sql.init` 建表方式。
- 业务表新增 `user_id`；`generation_task` 增加 `billing_op_id`、`credit_cost`，幂等唯一键改为 `(user_id, idem_key)`。
- 新增 `app_user`、`auth_token`、`mcp_token`、`member_plan`、`credit_package`、`wallet`、`credit_ledger`、`usage_counter`、`payment_order`、`payment_notify_log`、`audit_log`、`event_outbox`、`event_inbox`。

### 后端

- 新增 `user`：数据库 UserDetailsService、注册/邮箱验证/找回密码、`AuthUser`/`UserContext`、个人 MCP Token、管理员初始化与旧数据归属、登录审计。
- 新增 `member`/`billing`：三档会员播种与权益解析、清晰度限制、钱包冻结/实扣/退回、日额度、按模型计价、账户摘要与流水。
- 新增 `payment`：订单状态机、Mock 支付、微信支付 V3 Native（RSA 签名 + AES-GCM 解密）、支付宝电脑网站支付（RSA2 签名/验签）、回调幂等到账、过期关单。
- 新增 `mq`：事务 Outbox、进程内唤醒队列、可选 RabbitMQ 发布/消费、失败重试与死信。
- 新增 `audit` 与管理后台接口：用户/角色/会员调整、会员档位、积分商品、订单、审计、Outbox 死信重投。
- 改造 `SecurityConfig`/`McpAuthenticationFilter`：数据库用户、用户级 Bearer Token、旧全局 Token 兼容映射管理员、公开认证接口与支付回调放行。
- 改造 `WorkspaceService`、`TaskService`、`CanvasNodeService`、`TaskDispatcher`：归属校验、用户维度幂等、计费接入、个人+平台双重并发、会员权重调度、失败/超时/取消退回。
- 改造 WebSocket：握手绑定用户并校验画布归属；新增 `FileAccessController` 替换公开静态目录，按用户目录与数据库记录校验文件归属。
- 存储：新素材使用 `{userId}/...` 路径；第三方产物转存失败改为抛错，不再保存第三方 URL。
- MCP 工具：`McpToolSupport` 改为 Spring Bean，未指定画布时使用当前用户第一个画布。

## 影响面

- 首次启动会执行 V2 迁移并初始化管理员，旧画布/素材/任务统一归属管理员；旧 Session 与旧 CLI 会话需要重新登录。
- 默认存储类型仍为 `cos`，本地开发需显式设置 `AIGC_STORAGE_TYPE=local`（测试已设置）。
- 生成接口新增 402 语义；前端、CLI、MCP 调用方需要识别 `INSUFFICIENT_BALANCE`、`QUOTA_EXCEEDED`、`EMAIL_NOT_VERIFIED`。
- 部署需要为真实邮件/支付/MQ 增加环境变量；支付回调必须公网 HTTPS。

## 遗留问题

1. 真实 SMTP、微信/支付宝回调、RabbitMQ、MySQL 5.7 需在具备凭据/实例的环境追加联通验收。
2. 本地旧文件路径仍可被已登录用户访问，归属按数据库记录校验；建议后续统一迁移到用户目录。
3. Session 未集中吊销，禁用账号或重置密码后已有登录态不会立即失效。
4. 余额不足/额度耗尽当前直接返回 402，不创建失败任务记录。
5. 支付适配采用与 IJPay 2.9.7 等价的直连协议实现，未引入 IJPay 依赖；如必须使用 IJPay，可在 `payment` 渠道层替换。
6. V2 未强制 `user_id NOT NULL`，以兼容旧数据初始化顺序；归属非空仍由应用层保证。
7. 前端采用 Hash 路由（`/#/workspaces` 等），与计划草图的无 `#` 路径不同，原因是后端只托管 `/`；如后续需要无 `#` 路由，需同时调整 Spring 静态资源与鉴权放行规则。
8. 支付宝电脑网站支付返回的 `formHtml` 通过 `v-html` 渲染，浏览器不会执行其中的自动提交脚本，需由用户点击确认；生产接入时建议改为表单提交或跳转支付链接。
