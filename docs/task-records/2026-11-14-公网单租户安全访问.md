# 2026-11-14 公网单租户安全访问

## 1. 需求背景

项目部署到公网后，原先可匿名访问的 MCP、REST、WebSocket 和本地媒体文件会带来画布数据泄露及被他人操作的风险。本次按个人/小团队使用的**单管理员、单租户**模型实施访问控制：未登录用户只能看到登录页，网页与 MCP 使用相互独立的凭证，对象存储不再依赖永久公共读。

安全边界如下：

- 网页：账号密码登录，后端 Session，写操作启用 CSRF 防护。
- MCP：`/sse`、`/mcp/message` 使用独立 `Authorization: Bearer <MCP_API_TOKEN>`，网页 Session 不能替代。
- WebSocket 与 `/files/**`：必须持有有效网页 Session，并限制 Origin。
- MinIO / COS / OSS：私有对象，响应阶段生成短期 GET 签名 URL，数据库仍保存稳定 URL。
- 管理员密码和 MCP Token 只通过环境变量配置，无默认密钥，真实 Token 不下发前端。

## 3. 启动与部署要点

启动前必须显式配置：

```powershell
$env:AIGC_ADMIN_USERNAME='admin'
$env:AIGC_ADMIN_PASSWORD='替换为强密码'
$env:MCP_API_TOKEN='替换为至少32字符的高强度随机Token'
```

公网 HTTPS 部署还需设置：

```powershell
$env:AIGC_COOKIE_SECURE='true'
# 仅前后端分离或确有跨域需求时设置：
$env:AIGC_ALLOWED_ORIGINS='https://canvas.example.com'
```

- MCP 客户端配置 `Authorization: Bearer <MCP_API_TOKEN>`，不要把真实 Token 写入前端或仓库。
- 反向代理需传递 `Forwarded` / `X-Forwarded-*`，并正确转发 `/sse`、`/mcp/message` 和 WebSocket Upgrade。
- 使用云存储时保持桶/对象为私有；已有 MinIO 公共读策略需人工收紧。
- 本次为完成打包已停止原 8080 旧服务，配置上述环境变量后再启动新版本。

## 5. 影响面与兼容性

- 原有匿名 REST 调用不再可用：浏览器写请求需先登录并携带 CSRF Header，MCP 客户端需增加 Bearer Token。
- 当前仅一个管理员身份，所有登录者共享画布；没有用户注册、角色、工作空间归属或多租户数据隔离。
- Session 默认保存在单实例内存中，重启会使登录失效；多实例部署需要粘滞会话或引入 Spring Session。
- 默认同源访问，前后端分离部署必须显式配置 Origin 白名单。
- 本地媒体继续返回 `/files/**` 相对地址；云存储仅响应中的访问地址带签名，持久化数据与幂等逻辑不变。
- 签名 URL 到期后需要重新拉取节点数据；外部视频供应商必须能在签名有效期内访问参考图。
- H2 Console 默认关闭，如本地确需使用须显式开启并评估暴露风险。
