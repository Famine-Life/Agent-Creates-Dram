# 2026-11-14 新增腾讯云 COS / 阿里云 OSS 图床

## 1. 需求背景

除本地磁盘、MinIO 外，需要把「腾讯云 COS」和「阿里云 OSS」也作为可选图床/对象存储，用于存放参考图和生成成片，并且可以只改配置切换、不改代码。

## 2. 改动清单

| 文件 | 改动 |
| --- | --- |
| `server/pom.xml` | 新增 `com.qcloud:cos_api:5.6.227`、`com.aliyun.oss:aliyun-sdk-oss:3.17.4` |
| `config/StorageProperties.java` | 新增 `cos` / `oss` 两组配置（endpoint、凭据、bucket、region、public-url） |
| `storage/AssetStorage.java` | 新增 `owns(url)` 默认方法，用于判断地址是否已属于当前存储 |
| `storage/BucketUrl.java` | 新增地址拼接工具：优先 `public-url`，否则按 `bucket + endpoint` 生成默认域名（兼容带/不带 scheme、endpoint 已含 bucket 的写法） |
| `storage/CosAssetStorage.java` | 新增腾讯云 COS 实现（`@ConditionalOnProperty` 按 `type=cos` 启用，懒加载 `COSClient`，上传后返回外链） |
| `storage/OssAssetStorage.java` | 新增阿里云 OSS 实现（`type=oss`，懒加载 `OSS`，上传后返回外链） |
| `storage/MinioAssetStorage.java` | 实现 `owns()`，把「是否已在本存储」的判断从 `AssetService` 下沉 |
| `storage/AssetService.java` | 转存判断改为 `storage.owns()`；启动时打印当前存储实现 |
| `resources/application.yml` | `type` 支持环境变量 `AIGC_STORAGE_TYPE`；新增 `aigc.storage.cos.*`、`aigc.storage.oss.*`（凭据均走环境变量） |
| `docs/architecture.md` | 存储、技术栈、配置表同步补充四种存储 |

## 3. 使用方式

```powershell
# 腾讯云 COS
$env:AIGC_STORAGE_TYPE='cos'
$env:COS_ENDPOINT='https://aigc-1250000000.cos.ap-guangzhou.myqcloud.com'
$env:COS_SECRET_ID='...'
$env:COS_SECRET_KEY='...'
$env:COS_BUCKET='aigc-1250000000'
$env:COS_REGION='ap-guangzhou'
# 可选：CDN / 自定义域名
$env:COS_PUBLIC_URL='https://cdn.example.com'

# 阿里云 OSS
$env:AIGC_STORAGE_TYPE='oss'
$env:OSS_ENDPOINT='https://oss-cn-hangzhou.aliyuncs.com'
$env:OSS_ACCESS_KEY_ID='...'
$env:OSS_ACCESS_KEY_SECRET='...'
$env:OSS_BUCKET='aigc-demo'
$env:OSS_PUBLIC_URL='https://cdn.example.com'
```

- 参考图上传成功后返回 COS/OSS 外链，画布图片节点直接展示该外链；
- 视频生成成功后由 `AssetService.transfer` 转存到当前存储；
- 需保证桶为**公共读**（或经 CDN 公开访问），否则前端无法直接播放/显示；
- `public-url` 为空时，COS 用 `https://{bucket}.{endpoint-host}`、OSS 用 `https://{bucket}.{endpoint-host}` 拼接。

## 4. 验证

| 项目 | 结果 |
| --- | --- |
| `mvn -DskipTests package`（JDK 17） | PASS |
| `--aigc.storage.type=cos` 启动（8081，H2 内存库，假凭据） | PASS：仅装配 COS 实现，容器正常启动 |
| `--aigc.storage.type=oss` 启动（8081，H2 内存库，假凭据） | PASS：仅装配 OSS 实现，容器正常启动 |
| 默认 `local` 重启 8080 | PASS：`/api/meta`、`/api/canvas/1` 正常，原画布数据完整 |
| 真实上传/下载 | 未验证，需要真实的桶与密钥（启动阶段不会发起网络请求） |

> 构建时发现机器默认 `JAVA_HOME` 指向 JDK 8，会导致 record/switch 表达式编译失败；需显式使用 `C:\Program Files\Java\jdk-17`。

## 5. 影响面与兼容性

- 默认仍为 `local`，现有部署无需改动；
- 新增依赖不参与默认存储路径，不影响启动速度（客户端懒加载）；
- 前端无需改动，外链与 `/files` 地址在数据里都是普通 URL。

## 6. 遗留问题 / 下一步

- 未提供「删除远端对象」能力（目前只增不删）；
- COS/OSS 上传未做失败重试与分片上传，大视频依赖单次 PUT；
- 如使用私有桶，需要额外实现签名 URL（当前设计假设公共读或 CDN）。
